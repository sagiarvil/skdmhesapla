## H1 · KATASTROFİK — `MAX(DB_lastmod, Current_Epoch)`

Kaynak §1.2 şunu söylüyor:

```
MAX(DB_lastmod, Current_Epoch) fonksiyonuyla korunur
```

**Bu her URL'nin `lastmod` değerini her build'de "şu an" yapar.** Geçmiş bir tarih ile
şu anın maksimumu daima şu andır. Sonuç: sitenin tamamı her deploy'da "az önce
değişti" der. Google `lastmod` güvenilirliğini bu şekilde kaybeder ve etiketi tümden
yok saymaya başlar — <cite index="12-1">`lastmod` değerinin gerçeklikle tutarlı olması şarttır</cite>.

Daha kötüsü: aynı belgenin §5 TypeScript kodu **tam tersini** yapıyor:

```typescript
const safeLastMod = page.updated_at > serverEpoch ? serverEpoch : page.updated_at;
```

Bu `MIN`'dir ve **doğrudur** — gelecek tarihi bugüne kırpar. Belge kendi kodunu
yanlış tarif etmiş.

**DOĞRU KURAL:**
```
lastmod = MIN(DB_lastmod, Server_Epoch)     ← gelecek tarihi kırp
lastmod ASLA build/deploy/crawl zamanı değildir
Tarih güvenilir değilse <lastmod> TAMAMEN OMIT edilir
```

## H2 · OBSOLET — Google ping endpoint

Kaynak NODE 6 sitemap'i Google'a ping'lemeyi söylüyor. <cite index="10-1">Google 2023'te sitemap ping desteğini kaldırdı; endpoint'e yapılan istekler 404 döner ve robots.txt ile Search Console dışında bir yol kalmadı</cite>. <cite index="9-1">Gerekçe olarak gönderimlerin ezici çoğunluğunun spam olduğunu belirtti</cite>.

**YERİNE:**
- **Google:** `robots.txt` içinde `Sitemap:` satırı + Search Console API (`sitemaps.submit`).
  Başka yol yok. Indexing API yalnızca `JobPosting` ve `BroadcastEvent` kapsamındadır.
- **Diğerleri:** IndexNow. <cite index="19-1">Bing, Yandex, Seznam ve Naver destekler; tek gönderim hepsine ulaşır. Google katılmadı. Sitemap'in yerine geçmez — sitemap kapsam içindir, IndexNow değişiklik bildirimidir</cite>.
- **Neden önemli:** <cite index="20-1">Bing indeksi ChatGPT Search, Copilot ve Perplexity'yi besler</cite>. AI arama görünürlüğü buradan geçer.
- **Uyarı:** <cite index="19-1">IndexNow'un yayınlanmış günlük limiti yok ama motorlar sunucu tarafında hız sınırı ve kalite puanlaması uygular; düşük kaliteli sayfalarla spam yapmak sonraki gönderimlerinizin ciddiye alınma oranını düşürür</cite>. Yalnızca **anlamlı içerik değişikliğinde** gönderin, stil/düzen değişikliğinde asla.

## H3 · ÇELİŞKİLİ — `Cache-Control: no-store` + ETag

Kaynak NODE 5 hem `no-cache, no-store, must-revalidate, max-age=0` diyor hem de
"Googlebot aynı ETag'i görürse taramayı iptal eder" diyor. **`no-store` ETag
revalidasyonunu iptal eder.** İkisi bir arada anlamsızdır ve CDN'i devre dışı bırakır.

**DOĞRU:**
```
Cache-Control: public, max-age=300, must-revalidate
ETag: "<child XML SHA-256>"
Content-Type: application/xml; charset=utf-8
```
`304 Not Modified` yanıtı bant genişliğini korur; `no-store` bunu imkânsız kılar.

## H4 · UYDURMA MATEMATİK — `W(url)` formülü

```
W(url) = (PageRank_score * Traffic_weight) / (Depth_from_root + 1)
```

İki sorun: (a) `PageRank_score` site sahibine **açık değildir**, ölçülemez;
(b) hesaplanan ağırlık sitemap XML'ine **yazılamaz** — çünkü aynı belge doğru şekilde
`priority` etiketinin yok sayıldığını söylüyor. <cite index="9-1">Google changefreq ve priority elemanlarını kullanmıyor</cite>.

**KARAR:** Formül sitemap'ten çıkarılır. Derinlik/trafik ağırlığı **iç bağlantı
mimarisi** ve **crawl bütçesi teşhisi** için kullanılabilir — XML'e girmez.
Sitemap'te yalnız `<loc>` ve `<lastmod>` bulunur.

## H5 · TASARIM HATASI — `throw new Error(LIMIT_EXCEEDED)`

Kaynak kodu 50.000 URL'ye ulaşınca **tüm üretimi patlatıyor**. Site büyüdüğünde
sitemap üretimi tamamen durur. Doğrusu: yeni chunk dosyasına **devret** (roll over),
index'e ekle, devam et. Sınır aşımı bir hata değil, normal büyümedir.

## H6 · SESSİZ RİSK — `renameSync` ve gzip adlandırma

- `renameSync` yalnızca **aynı dosya sisteminde** atomiktir. `./tmp` → `./public`
  farklı mount ise atomik değildir; `EXDEV` hatası veya yarım dosya riski doğar.
  **Kural:** temp dosya hedefle aynı dizinde oluşturulur (`./public/.sitemap.tmp`).
- Kod `sitemap-main.xml.gz` yazıyor ama index `.xml` referans veriyor.
  Gzip servis edilecekse `Content-Encoding: gzip` + doğru `Content-Type` zorunlu,
  yoksa tarayıcı/bot bozuk XML görür.

# I. TEMEL DOKTRİN

Sitemap bir dosya değil, veritabanı durumunun taranabilir yüzeyidir. Üç kural:

1. **Kirli URL yasaktır.** 404, 301, `noindex`, canonical uyumsuzu, parametreli URL
   sitemap'e giremez. Kirli URL crawl bütçesi israfıdır.
2. **`lastmod` bir tahmin değildir, kanıttır.** Kanıt yoksa etiket yoktur.
3. **Belirsizlikte üretim durur.** Baseline okunamıyorsa, veri boşsa, hash
   deterministik değilse — Last Known Good korunur, deploy yapılmaz.

## Etiket politikası (kesin)

| Etiket | Karar |
|---|---|
| `<loc>` | ZORUNLU — mutlak, canonical, parametresiz |
| `<lastmod>` | ZORUNLU (güvenilirse) — W3C Datetime, UTC |
| `<priority>` | **YASAK** — üretilmez |
| `<changefreq>` | **YASAK** — üretilmez |
| `<xhtml:link hreflang>` | Çok dilli sitede zorunlu, çift yönlü |

Yalnız `image:`, `video:`, `news:` namespace'leri **fiilen kullanılıyorsa** eklenir.
Kullanılmayan namespace bildirimi gürültüdür ve doğrulamayı zorlaştırır.

# II. `lastmod` SEMANTİĞİ — iki seviye, asla karışmaz

```
URL   <lastmod> = sayfanın son ÖNEMLİ İÇERİK değişikliği
INDEX <lastmod> = child sitemap DOSYASININ son gerçek değişikliği
```

## Neden `MAX(URL lastmod)` yasak

```
A lastmod = 2026-08-01
B lastmod = 2026-07-15
C lastmod = 2026-06-20
```

C silinirse child dosya **değişir**, ama `MAX` hâlâ `2026-08-01` kalır.
Değişiklik sessizce kaybolur. Bu yüzden index `lastmod` **içerik hash'inden** türetilir.

## Durum makinesi

| Durum | Koşul | `lastmod` eylemi |
|---|---|---|
| **UNCHANGED** | `new_hash == live_hash` | **PRESERVE** — canlıdaki güvenilir tarih korunur |
| **CHANGED** | `new_hash != live_hash` | **SET_NOW** — finalization anında tek UTC damgası |
| **NEW** | canlıda yok, build'de var | **SET_NOW** |
| **REMOVED** | canlıda var, build'de yok | index'ten **tamamen çıkar** |
| **BASELINE_UNKNOWN** | baseline okunamıyor | **DEPLOY FAIL** — tarih uydurulmaz |

## Deterministik üretim (hash'in ön koşulu)

Aynı semantik girdi → aynı byte → aynı SHA-256.

```js
entries.sort((a, b) => a.loc.localeCompare(b.loc, 'en'))
```

**YASAK:** filesystem sırası, locale-bağımlı sıralama, XML içine build timestamp,
random UUID, deterministik olmayan whitespace, her build değişen generator metadata.

> Kaynak belgede bu satır `a.loc.localeCompare(b, 'en')` yazılmış — ikinci argüman
> `b.loc` olmalı, `b` değil. Nesneyi string'e çevirir ve sıralama bozulur.

# IV. KİRLİ URL GÜVENLİK DUVARI

Bir URL sitemap'e girmeden önce **hepsini** geçmelidir:

| Kontrol | Ret koşulu |
|---|---|
| HTTP durumu | `!== 200` |
| Robots meta | `noindex` var |
| X-Robots-Tag | `noindex` var |
| Canonical (DOM) | self-canonical değil |
| Canonical (Header) | DOM canonical ile uyuşmuyor |
| URL normalizasyonu | tracking/query parametresi var (`utm_*`, `ref`, `fbclid`, `gclid`) |
| Yetim sayfa | root'tan iç bağlantıyla erişilemiyor veya `depth > maxDepth` |
| Yinelenen | normalize edilmiş URL zaten listede |
| robots.txt | `Disallow` kapsamında |
| Hreflang | karşılık çift yönlü değil |

**Tek gerçek kaynağı (SSOT) dört bileşen paylaşır:** HTML `<link rel="canonical">`,
HTTP `Link` header, sitemap `<loc>`, `robots.txt` içindeki `Sitemap:` satırı.
Biri bile uyuşmazsa → `CANONICAL DRIFT` → o URL sitemap'e girmez.

**Parametre beyaz listesi:** yalnızca `?page=` gibi onaylı parametreler geçer.
Bu, kaynak belgedeki "parameter injection ile index bloat" saldırısının savunmasıdır
ve gerçek bir risktir.

# V. FAIL-SAFE DOKTRİNİ

| Senaryo | Zorunlu davranış |
|---|---|
| **0 URL** | Stream **AÇILMAZ**. Eski sitemap CDN'de kalır. `P0` alarmı. Boş `<urlset>` yayınlamak toplu de-indeksleme riskidir. |
| **DB kopması** | `try/catch/finally` → temp dosya **silinir**. Canlı sitemap ezilmez. |
| **Baseline okunamıyor** | `BASELINE_UNKNOWN` → **DEPLOY FAIL**. Tarih uydurulmaz. |
| **Validation fail** | Atomic rename yapılmaz, önceki artifact korunur. |
| **URL sayısı ani düşüş** | Canlıya göre **>%20 azalma** → deploy durur, insan onayı ister. |

Son satır kaynak belgede yoktu ve gerçek bir boşluktu: kısmi veri kaybı 0 URL değildir,
fail-safe'i tetiklemez, ama sitenin yarısını index'ten düşürebilir.

## Baseline retry
```
8 deneme · connect timeout ≤ 10 sn · request timeout ≤ 30 sn · retry delay ≥ 5 sn
```

## Atomic write
```
write ./public/.sitemap.tmp   (hedefle AYNI dizin — H6)
validate temp
atomic rename → ./public/sitemap.xml
```

## Migration guard
İlk geçişte eski `MAX(URL lastmod)` tarihleri güvenilir baseline sayılmaz:
```
SEO_SITEMAP_INDEX_MIGRATION=1     ← yalnız BİR kez
```
CI kuralı: bu bayrak **ardışık iki deploy'da açıksa FAIL**. Bootstrap mekanizmasının
kalıcı `Date.now()` hilesine dönüşmesi engellenir.

# XIII. KAPSAM DIŞI — dürüstlük maddesi

Bu manda **sitemap boru hattını** kusursuzlaştırır. Sıralama getirmez.

Sitemap bir **keşif** aracıdır, **sıralama** aracı değildir. Kusursuz bir sitemap
şunları yapar: yeni sayfalar daha hızlı keşfedilir, crawl bütçesi israf edilmez,
kirli URL index'i şişirmez. Şunları **yapmaz**: içeriği daha iyi hale getirmez,
backlink kazandırmaz, arama amacına (search intent) uyumu artırmaz, rakibinizin
daha iyi içeriğini yenmez.

Altı siteniz için sıralama sırası şudur ve ağırlıkları bu sıradadır:

1. **Arama amacına gerçekten cevap veren içerik** — en ağır kalem, farkla
2. **Teknik erişilebilirlik** (Core Web Vitals, render, mobil)
3. **İç bağlantı mimarisi** — H4'teki derinlik/ağırlık analizinin gerçek yeri burasıdır
4. **Yapılandırılmış veri** (JSON-LD) — AI aramada zorunlu hale geliyor
5. **Sitemap hijyeni** — bu manda

Sitemap'i 10/10 yapıp 1. maddeyi ihmal ederseniz sonuç değişmez. Bu mandayı
uygulayın, sonra enerjinizi içeriğe verin.
